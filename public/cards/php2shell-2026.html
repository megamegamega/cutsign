PHP2Shell emergency release

Two unauthenticated RCE flaws in the PHP engine — CVE-2026-109618 / CVE-2026-109619, CVSS 4.0 9.2 — leaked ahead of coordinated disclosure, patched in an emergency release October 21. Cloudflare has observed millions of exploitation attempts, some delivering the Mirai-derived Potassium botnet; watchTowr has observed in-the-wild exploitation of both CVEs. As of Oct 26 exploitation is confirmed working, not just scanning: researchers took over an Apache mod_php honeypot, a European government entity was compromised with agentic-AI post-exploitation, and Mirai operators plus ASLR-bypass exploits have joined.

On Cutsign: leak story 10-21 patch update 10-22 mass exploitation 10-23 CISO card IoC card (20) news & updates (live)

Verdict: patch outside the normal cycle, and hunt while you patch. Unauthenticated RCE in the engine that runs most of the web, with exploitation observed in the wild and mass probing underway — this does not wait for the monthly window. Successful compromises are now confirmed (Oct 24–26) — treat unpatched internet-facing PHP as presumed targeted, and hunt back to Oct 20 when the details leaked. PHP 7.4 / 8.0 / 8.1 get no binary release — official source-backport branches and distro packages are the only routes, and migration is the real fix. The PHP team published official interim mitigations (below) for installations that cannot patch today. Hunting behaviors are published and concrete, which makes this one of the rare patch events that is also immediately huntable.

30-second read

Both flaws are use-after-frees in PHP core (session upload-progress handling and fatal-error paths), reachable without authentication. Observed exploitation recycles PHP workers, leaks memory through PHPSESSID cookies, and abuses session upload-progress handling to run shell commands; the observed exploit targets Apache mod_php, and exploitation is easier where session upload-progress is enabled. Some attempts fetch a Potassium loader from 92.118.112[.]100.

Official mitigations (php.net) — if you cannot patch today

From the PHP team's advisory: these reduce exposure to the confirmed paths but "do not make an installation safe" — patching is the fix.

# CVE-2026-109619 (stale global state) — blocks the confirmed session path:
session.upload_progress.enabled=0     ; php.ini / FPM pool / server config,
                                      ; NOT ini_set() or .user.ini — then restart every worker
fatal_error_backtraces=0              ; PHP 8.5 only, blocks the fatal-backtrace path

# CVE-2026-109618 (OOM corruption) — starve the allocation-failure primitive:
memory_limit=-1                       ; via php_admin_value so apps cannot override
post_max_size = 8M                    ; (32M if uploads needed); upload_max_filesize below it
# plus web-server/proxy limits on decoded size, field/part/header counts, nesting —
# enforced even without a usable Content-Length
# availability boundary: container/cgroup limit killing only the worker.
# Do NOT use RLIMIT_AS / RLIMIT_DATA — they can trigger the vulnerable allocation failure.

Exposed if

  • Internet-facing PHP below the fixed versions — the probing is indiscriminate
  • PHP 7.4 / 8.0 / 8.1 or older anywhere, without a distro backport
  • Session upload-progress enabled and/or Apache mod_php (the observed exploit's target)

Not exposed if

  • PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 or later
  • A distribution backport patch is applied (verify by changelog, not version string)

Hunt — published behaviors

  • Unusual multipart requests followed by memory-limit errors or HTTP 500 bursts
  • Oversized or malformed PHPSESSID response cookies (memory-leak primitive)
  • Unexplained PHP worker churn / recycling
  • PHP worker processes (php-fpm, php-cgi, httpd, apache2) spawning shells, interpreters, or download tools; new webshells, cron jobs, accounts
  • Outbound fetches to 92.118.112[.]100 and the campaign infrastructure — raw values on the IoC card (20 indicators)

Inferred detections — while you wait

The behaviors above are published (Wiz, Huntress) but no vendor has shipped ready-made queries. These translate the published behaviors into generic query logic — tune thresholds to your traffic.

Exploit attempt shape — multipart request then memory error, from the same source:

# web / LB logs
multipart POST (content-type contains multipart/form-data)
followed within 60s by status 500 from same src_ip
| count by src_ip over 10m → investigate bursts; mass probing will be loud

Memory-leak primitive — the PHPSESSID leak is visible in responses:

# proxy / web logs with response headers
response Set-Cookie contains PHPSESSID AND cookie length > 1KB
→ near-zero false positives; any hit is an exploitation attempt that got traction

Post-exploitation lineage — the published Huntress behavior as a query:

# EDR process lineage
parent.name IN (php-fpm, php-cgi, apache2, httpd)
child.name IN (sh, bash, curl, wget, perl, python*)
also: php-fpm "child exited on signal" bursts in syslog (worker churn)

Splunk (index=*) — CIM Web / Endpoint field names, Sysmon names for lineage; tune to your add-on:

# exploit attempt shape: multipart POST then HTTP 500 from the same source inside 60 s
index=* earliest=-30d@d ((http_method=POST http_content_type="multipart/form-data*") OR status=500)
| transaction src maxspan=60s
| search http_method=POST status=500
| stats count as pairs min(_time) as first max(_time) as last values(uri_path) as paths by src
| sort - pairs
# memory-leak primitive: oversized PHPSESSID in responses
index=* earliest=-30d@d "Set-Cookie" "PHPSESSID"
| regex _raw="PHPSESSID=[^;\s]{1024,}"
| stats count by src dest uri_path
# post-exploitation lineage (Sysmon EID 1 / EDR)
index=* earliest=-30d@d ParentImage IN ("*/php-fpm*","*/php-cgi*","*/apache2","*/httpd")
    Image IN ("*/sh","*/bash","*/dash","*/curl","*/wget","*/perl","*/python*")
| stats count values(CommandLine) as cmds min(_time) as first by host ParentImage Image
# worker churn (syslog)
index=* earliest=-30d@d "php-fpm" "child" "exited on signal"
| timechart span=10m count by host
# campaign infrastructure (Potassium loader)
index=* earliest=-30d@d (dest=92.118.112.100 OR src=92.118.112.100 OR url="*92.118.112.100*")
| stats count min(_time) as first by host src dest
