GitLab 19.5.1 critical release

CVSS 10.0 unauthenticated RCE — CVE-2026-110264, an integer overflow compiling a crafted regular expression in the bundled Onigmo engine. Reaches every self-managed release since 7.0 (2014). Patched October 21.

On Cutsign: brief story 10-22 CISO card news & updates (live) IoC card: none — no indicators published

Verdict: patch lane, urgent tier — and beware the patch trap. The October 12 patch releases (for CVE-2026-97229 and others) do not cover this flaw: anyone who "already patched GitLab this month" before October 21 is still exploitable. No exploitation reported yet, but public PoC code is circulating, preconditions are undisclosed (assume reachable), and GitLab offers no workaround. GitLab.com and Dedicated tenants are already fixed — this is a self-managed problem.

30-second read

A crafted regex fed to the Onigmo engine overflows during compilation, giving unauthenticated remote code execution on self-managed GitLab — one public write-up demonstrates the path through a crafted Org-mode file render. GitLab patched its vendored copy rather than waiting on upstream, and has not disclosed which endpoints reach the compiler, so treat every unauthenticated surface as in scope. A PoC repository is public on GitHub (unverified — handle in a sandbox, never on infrastructure).

Inferred detections — while you wait

GitLab named two Sigma rules but the rule text is not in public sources, and scanners have nothing. The logic below reconstructs what those rules must look for, inferred from the flaw's shape (crafted regex → Onigmo crash during compile) — tune before trusting. These catch failed attempts; a clean exploit may leave neither.

Worker-crash canary — regex engine overflows crash Ruby workers before they succeed:

# host telemetry on GitLab servers
process.name IN (ruby, puma, sidekiq, gitlab-workhorse)
termination.signal = SIGSEGV
→ any occurrence on a GitLab host since Oct 20 is worth a look

Render-endpoint error bursts — the demonstrated path is a crafted Org-mode file render ("Org mode render error burst"):

# GitLab production_json.log / LB logs
status = 500 AND (path contains preview_markdown OR render OR blob
  OR requested file extension = .org)
| bucket 10m, count by src_ip → alert on bursts from a single source

Pre-patch inventory sweep — find the instances nobody registered:

# network / asset data
HTTP responses with header X-GitLab-* OR title "GitLab" on internal ranges
