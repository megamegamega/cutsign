jest-canvas-mock npm compromise (Mini Shai-Hulud, AntV wave)

On May 19, 2026 the npm maintainer account atool was hijacked and used to publish roughly 640 backdoored versions across about 320 packages in under half an hour — the AntV wave of the self-spreading "Mini Shai-Hulud" worm. jest-canvas-mock, a Jest test helper with about 3.2 million weekly downloads that sits in the devDependencies of front-end projects, received three of them: 2.5.3, 2.6.3 and 2.7.3. Installing any of the three ran a credential stealer on the developer laptop or CI runner doing the install.

On Cutsign: no brief story — May 2026 incident, carded on request news & updates (live) Shai-Hulud coverage (live)

Verdict: this is a six-month-old incident, not a new one — the job is a look-back, not a patch. The registry is clean today (2.5.8 is latest and fresh installs resolve to it). The open question is historical: did any laptop, CI runner or build image resolve 2.5.3, 2.6.3 or 2.7.3 on or after May 19 — and if so, treat every secret that machine could read as stolen, remove the persistence first, then rotate. The payload plants hooks (a kitty-monitor daemon, Claude Code and VS Code auto-run entries, a secrets-dumping GitHub workflow) that outlive a lockfile rollback, so "we already downgraded" does not close it.

30-second read

Two delivery routes are reported. 2.5.3 carries an optionalDependencies entry, @antv/setup, pointing at an orphan commit in the antvis/G2 fork network whose prepare script runs bun run index.js && exit 1 — it fails quietly because the dependency is optional. The wider wave used a preinstall hook running a ~500 KB obfuscated index.js under Bun. Either way the payload harvests environment variables and 130+ credential paths (AWS, GCP, Azure, SSH keys, npm and GitHub tokens, kubeconfig, Vault, Docker auth, Slack, crypto wallets, ~/.claude.json), reads masked secrets out of GitHub Actions runner memory, and ships them to t.m-kosche[.]com:443 dressed as OpenTelemetry traces, with a fallback that commits them to public GitHub repos created with the victim's own token. It then republishes the victim's npm packages with the worm inside.

Exposed if

  • Any lockfile, CI log, build cache or image layer shows jest-canvas-mock at 2.5.3, 2.6.3 or 2.7.3
  • A range (^2.x, ~2.5.x) was installed without a committed lockfile, or a lockfile was regenerated or bot-bumped, from 01:39 UTC May 19 onward
  • An internal registry proxy or cache (Artifactory, Nexus, Verdaccio) fetched one of the three — cached tarballs outlive the registry takedown
  • Any other atool-published version from that window resolved: echarts-for-react, timeago.js, size-sensor, jest-date-mock, @antv/* — same payload

Not exposed if

  • Lockfiles stayed pinned at ≤ 2.5.2 (or at 2.5.8) and installs use npm ci / --frozen-lockfile
  • Fresh installs today: ranges resolve to 2.5.8; 2.6.3 and 2.7.3 are gone from the registry
  • Production runtime: this is a test dependency — exposure is laptops and CI, not prod servers (unless prod images are built with devDependencies)
  • --ignore-scripts blunts the preinstall route; do not count on it for the 2.5.3 git-dependency route (not verified here)

Do now

  • Scope: search every lockfile and its git history since May 18 for the three versions, @antv/setup and commit 1916faa3…; then CI logs and registry-proxy caches. Purge cached tarballs
  • Sweep developer laptops and self-hosted runners for the persistence files — they survive a rollback, and log retention may not reach back to May
  • On a hit, order matters: isolate, remove the daemon and hooks first, then revoke. Snyk warns the token monitor may react to revocation, and the payload carries the string "IfYouInvalidateThisTokenItWillNukeTheComputerOfTheOwner"
  • Rotate everything the machine could read: npm and GitHub tokens, cloud keys, SSH keys, kubeconfig, Vault, database strings, Slack
  • Audit GitHub and npm: Dune-named public repos, the injected branch and workflow, unexpected publishes from your accounts after May 19
  • Block t.m-kosche[.]com at DNS and proxy; pin 2.5.8; use npm ci in CI

Escalation triggers

  • Any persistence artifact or C2 egress hit → incident lane, full rotation
  • kitty-monitor found running → the attacker had remote command execution for as long as it ran; scope as hands-on-keyboard
  • A Dune-named repo or results/results-*.json under your org or a staff account → those secrets were public; treat as disclosed
  • Package versions you did not publish, from your npm accounts or CI → you were a propagation node; notify npm and downstream users
  • Cloud audit logs showing the affected keys used from unfamiliar addresses since May 19

Not verified — read before relying on this card

  • When 2.6.3 and 2.7.3 were removed is not established (same day is implied, not timed), nor when 2.5.3's GitHub commit stopped resolving — so treat a 2.5.3 install on any date as exposed until shown otherwise
