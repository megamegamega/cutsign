LiteLLM 1.107.0 supply chain compromise

Attackers hijacked LiteLLM's release workflow (suspected leaked GitHub CLI OAuth token from an exposed internal deployment's logs) and published a backdoored 1.107.0 to PyPI, Docker Hub and GHCR on October 21. A cook.pth hook runs the "privcollect" credential stealer at every Python start on the host, even when litellm is never imported; sitecustomize.py forks an hourly remote-code loader.

On Cutsign: brief story 10-22 CISO card IoC card (11) news & updates (live)

Verdict: if 1.107.0 was installed, assume compromise — isolate, rebuild, rotate. This is not a patch decision; the exposure window is narrow (about two hours on PyPI, under three on Docker) but anything inside it ran a credential stealer with host-wide reach, and stolen AWS credentials were confirmed abused ~4.5 hours later (STS validation, then Bedrock enumeration — LLMjacking). Rotation scope is everything the host could see: cloud keys, browser-stored credentials, tokens in env vars and config.

30-second read

Seven wheels (Linux/macOS/Windows) each install three files into site-packages: cook.pth (loads at interpreter start), cook.py (privcollect — browser, AWS, GCP, Azure credentials; exfil as tar.gz POSTed to litellm[.]dev/healthcheck, a lookalike domain), and sitecustomize.py (Linux/macOS only: forks a daemon holding /tmp/remote_code_loader.lock that hourly fetches a C2 domain from a GitHub dead drop and executes <domain>/codepy). Socket's scanner flagged all seven wheels as malicious about 50 minutes after upload; PyPI pulled the release at 13:23 UTC.

Exposed if

  • Unpinned pip install litellm between 11:39–13:23 UTC, Oct 21
  • Docker/GHCR pull of v1.107.0, latest, main-latest, main-stable between 11:46–14:20 UTC, Oct 21
  • Any CI runner, dev laptop or build host that resolved the package in those windows — the stealer runs on every Python start, litellm imported or not

Not exposed if

  • Pinned to 1.106.2 (by digest) or anything other than 1.107.0
  • Installs resolved outside the windows (release was pulled)
  • Windows hosts escape the hourly loader (sitecustomize.py is Linux/macOS only) — but not the credential stealer
