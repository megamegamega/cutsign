BeyondTrust Remote Support zero-day

CVE-2026-102764 (BT26-05, CVSS 9.3): improper origin validation / authentication bypass in Remote Support (shared PRA code), exploited as a zero-day since late August 2026 by China-nexus espionage actor ARMORY CASTLE (UNC5221 / Warp Panda). Patched October 15; KEV-listed October 16 with a federal remediation deadline of October 19.

On Cutsign: brief stories 10-16 KEV story 10-19 CISO card IoC cards news & updates (live)

Verdict: for internet-facing appliances, this is assume-compromise, not patch-and-done. Six-plus weeks of pre-patch zero-day exploitation means patching only closes the door — the hunt reaches back to late August, and because the actor dumped the appliance credential vault (bt-secrets), a confirmed hit means rotating everything the appliance held: stored credentials, Jump Item targets, injected accounts. Remote-access appliances are where espionage actors live; Mandiant's hunt guidance is unusually concrete — use it.

30-second read

Post-exploitation chain: SAWFLY PHP webshell (mangoapi.php, staged as app_84304470%2Ephp) → root via a SUID copy of /bin/sh planted at /usr/bin/dbus-authd → vault dump with bt-secrets → persistence via a post_boot.d script (zz-root-persist) editing the sudoers template to survive reboot and patching → Jump Item roles raised to Administrator → BARECLAW SOCKS5/WebSocket tunneler behind a modified haproxy.conf (path /uidchanarge) → logs deleted. Scope note: sources dispute whether one or two vendor-confirmed instances were compromised; treat your own exposure as independent of that count.

Exposed if

  • Self-hosted Remote Support 26.2.3 or earlier, internet-facing — exact affected range wording differs between sources; verify against the vendor advisory
  • Privileged Remote Access sharing the flawed code path
  • Versions older than 24.3.1 must upgrade before they can take the patch — still exposed meanwhile

Not exposed if

  • Patched with BT26-05 and hunted clean back to late August (patching alone does not evict the sudoers persistence)
  • Cloud-hosted instances patched vendor-side — but review session/audit logs all the same

Do now

  • Patch BT26-05 (upgrade to ≥24.3.1 first where needed); restrict appliance exposure
  • Hunt back to late August: unknown .php POSTs and WebSocket paths at the reverse proxy; user_changed events raising Jump Item/team roles; file-transfer sessions by accounts whose roles changed
  • Host: SUID binaries (/usr/bin/dbus-authd), post_boot.d additions, sudoers-template edits, haproxy.conf ACL changes
  • Treat syslog-forwarding gaps bounded by a single session as tampering evidence
  • Confirmed hit → rotate the vault's entire contents and every injected credential

Escalation triggers

  • Any webshell/SUID/persistence artifact → full IR, vault-wide rotation, lateral-movement scoping
  • /login success from residential-broadband or commercial-VPN space; off-hours admin logins
  • New ARMORY CASTLE tooling or victims published
  • Exploitation expanding beyond espionage targeting (commodity adoption)

Inferred detections — while you wait

Mandiant's published queries (live above) come first. Generic translations for environments without appliance syslog in the SIEM:

# reverse proxy / WAF in front of the appliance
request.path not in (known Remote Support path set)
AND (path endswith .php OR websocket upgrade)
AND src not in (support staff + managed endpoint ranges)
# appliance syslog continuity (tamper canary)
no events from appliance for > N minutes, where the gap starts and ends
inside one admin session window → review that session's account and source
