NGINX2Root: NGINX HTTP/2 memory corruption

Two memory-corruption flaws in NGINX's HTTP/2 module, fixed November 18 in NGINX Open Source 1.30.7 and 1.31.9 and in NGINX Plus: CVE-2026-123007 (a flow-control counter underflow that ends in an out-of-bounds copy; any listener with HTTP/2 on, back to version 1.9.5) and CVE-2026-123633 (a use-after-free when connection slots run low; HTTP/2 plus proxying to a backend, back to 1.19.7). F5 scores both 8.1 (CVSS 3.1) and 9.2 (CVSS 4.0) and says code execution needs ASLR disabled or bypassed. Three research teams — Wiz, Xint and Rapid7 — say they bypassed ASLR and ran code as the NGINX worker in lab tests, without a login; Rapid7 published proof-of-concept scripts for one build. They are part of Xint's "NGINX2Root" set: five NGINX flaws fixed in the same release, plus a Linux kernel flaw with no patch yet that takes a compromised worker to root on the host. As of Nov 18 no source reports exploitation in the wild and neither CVE is in CISA's KEV catalog.

On Cutsign: not in a brief yet — published after the Nov 18 brief news & updates (live) same week: Java4Shell card

Verdict: patch outside the normal cycle; where a fixed package does not exist yet, turn HTTP/2 off on the listener. This is memory corruption reachable without a login in the most widely deployed web server and reverse proxy, three independent labs report working code execution, and proof-of-concept code was public on the day of the fix. What tempers it: exploitation is hard and build-specific. Rapid7's route for CVE-2026-123007 is tied to one build and needs roughly 119 GiB sent down a single connection — minutes on a fast link, not achievable below about 300 Mbit/s inside NGINX's default one-hour connection lifetime — so worker crashes are the likelier first effect, and the attempt is loud in flow data. The gap is the supply chain: Debian marks every release vulnerable, the community ingress-nginx controller is archived and will not ship this fix, and products built on NGINX need their own rebuilds. Access logs do not record the trigger, so hunting is a tripwire on the worker process, not a log search.

30-second read

CVE-2026-123007: when a canceled stream's queued data is discarded, NGINX returns its flow-control credit without checking the HTTP/2 maximum. A later unsigned check wraps, the send window grows far past its limit, and the oversized value reaches the TLS send path as a bad length for a memory copy — out-of-bounds read and write. A server that only serves static files is reachable; no backend or third-party module is needed (Wiz). CVE-2026-123633: an HTTP/2 connection waiting on a partial frame stays on the reusable-connection list; when the worker runs short of connection slots it can close and free that connection while a proxied request is still using it. A failed attempt crashes a worker, the replacement has the same memory layout, and the attacker can try again (Xint). Code runs as the worker account; reaching root needs the separate kernel step.

Interim mitigation — if a fixed build is not running yet

From Wiz, Xint and CIRCL. F5's own CVE records list no workaround. Turning HTTP/2 off blocks these two CVEs only, and breaks gRPC and anything else that needs HTTP/2.


# nginx 1.25.1 and later: in every server block that shares the address and port (IPv6 too),
# and remove "http2" from the listen lines

http2 off;

# nginx 1.9.5 to 1.25.0: was "listen 443 ssl http2;"

listen 443 ssl;

# restart, not reload, so connections held by old workers are dropped

systemctl restart nginx

# confirm from outside: the answer must not negotiate h2

openssl s_client -connect <host>:443 -alpn h2 </dev/null 2>/dev/null | grep -i alpn

# the worker-to-root step has no kernel patch: stop the SCTP module loading where it is not used
# (does not unload a module already loaded, or SCTP built into the kernel)

echo 'install sctp /bin/false' > /etc/modprobe.d/disable-sctp.conf

Exposed if

  • CVE-2026-123007: any listener with HTTP/2 on, NGINX Open Source 1.9.5 to 1.30.6 or 1.31.0 to 1.31.8, NGINX Plus R33 and later before the fixed builds — static-file servers included
  • CVE-2026-123633: HTTP/2 on and requests proxied to a backend, from 1.19.7
  • Anything built on NGINX until it is rebuilt: ingress controllers, API gateways, proxy managers, appliances, container images
  • Host root, not just the worker: the kernel's SCTP code is reachable (Linux 4.15 and later; many distributions load the module on first use). Containers share the host kernel

Not exposed if

  • A fixed build is what is running (restarted since the update)
  • HTTP/2 is off on every listener, confirmed by the ALPN check — for these two CVEs only
  • A distro backport is applied, confirmed by package revision
  • Partly: an edge or CDN that terminates the client's HTTP/2 itself may shield the origin, depending on the implementation (Wiz); an origin reachable directly is still exposed
  • Does not count: ASLR or PIE being on. The researchers bypass both; CIRCL says not to close or downgrade a finding on them

Hunt — published behaviors

  • An NGINX worker starting any program, a shell above all — the strongest sign of success (Xint, Upwind, CIRCL)
  • Worker crashes: exited on signal 11 in the error log, core dumps, restart bursts. Crashes have other causes too
  • One long-lived connection that receives far more than it sends, next to many short TLS connections from the same source (Xint; Rapid7's route sends about 119 GiB)
  • SCTP sockets opened, or the SCTP module loaded, on a web-server host or container node (Upwind)
  • Unusual outbound connections or DNS from the worker (CIRCL)

Access logs do not show the trigger: it travels in HTTP/2 control frames (WINDOW_UPDATE, RST_STREAM), which NGINX does not log as requests. A clean access log rules nothing out. No campaign infrastructure is published, so there is nothing to block by indicator.


# host checks published by Xint

grep -Ei 'worker process.*exited|signal 11|segfault' /var/log/nginx/error.log
coredumpctl list nginx
ss -tinp state established '( sport = :443 )'       # look for bytes_received racing ahead of bytes_sent

# audit rule for programs started by the worker account; records only from the moment it is installed

auditctl -a always,exit -F arch=b64 -S execve,execveat -F euid=<nginx uid> -k nginx_worker_exec
ausearch -k nginx_worker_exec -ts recent -i

Standing caveats: a version banner does not show a distro backport; host scans miss NGINX inside container images, ingress controllers and appliances; a scan reads the installed version, not whether the running workers were restarted.

Do now

  • Inventory every NGINX, including ingress controllers, gateways, proxy managers, appliances and container images built on it; note which listeners have HTTP/2 on and which proxy to a backend
  • Upgrade to NGINX Open Source 1.30.7 or 1.31.9, or NGINX Plus 37.0.8.1 or 37.3.0.1, internet-facing first; rebuild images, then restart rather than reload
  • Where no fixed package exists yet (distro packages, the archived community ingress controller, products built on NGINX), turn HTTP/2 off on every listener, restart, and confirm with an ALPN check
  • Block the SCTP kernel module on hosts and container nodes that do not use it; the worker-to-root step has no kernel patch yet
  • Put a tripwire on the worker: alert on any program started by the NGINX worker account, and on worker crash bursts
  • Plan the move off the archived community ingress-nginx controller; it will not receive this fix

Escalation triggers

  • CISA KEV listing or a credible report of exploitation in the wild → emergency change; HTTP/2 off on anything not yet fixed
  • An NGINX worker starts a shell or any unexpected program → incident lane; treat the TLS private keys and backend credentials that worker could read as exposed
  • Worker crash bursts on an internet-facing listener together with one long-lived, inbound-heavy connection → incident lane
  • Exploit code generalizes: a proof of concept that covers distro builds, or the withheld Wiz or Xint chains are published
  • A kernel fix for the SCTP flaw ships → patch kernels on NGINX hosts and container nodes

Inferred detections — while you wait

The researchers published host commands (above) but no ready-made log queries, and no vendor has shipped rules. These translate the published behaviors into generic query logic. They are inferred: tune thresholds to your traffic before trusting them, and anything published above supersedes them.

Worker tripwires — a crash is the likely first effect, a child process is the sign of success:


# nginx error log / kernel log
"worker process <pid> exited on signal 11"  OR  "nginx ... segfault at"
| count by host per hour → a burst on an internet-facing listener is the canary

# EDR process lineage
parent.name = nginx AND child.name != nginx
→ a stock NGINX worker starts no programs; any hit needs an explanation

The transfer the exploit needs — one source pushing tens of gigabytes into port 443 and getting little back:


# network flow / firewall logs
dest_port = 443, sum bytes client→server by src, dest
client→server ≥ 50 GiB AND client→server > 20 × server→client
→ uploads and backups to a web app look the same: exclude known upload endpoints

The worker-to-root step — SCTP coming to life on a web host:


# process events / kernel log
modprobe run with "sctp" or "proto-132" on the command line (the kernel loading the module on first use)
kernel message "sctp: Hash tables configured"
→ on a host with no SCTP workload, either is worth a look

Splunk (index=*) / Elastic ES|QL (FROM logs-*) — CIM Network Traffic / Endpoint field names for Splunk, ECS for Elastic, Sysmon names for process events; tune to your add-on or integration, and check which direction your sensor counts as inbound:


# worker crash canary: NGINX error log and kernel log, per host per hour

index=* earliest=-14d@d (("worker process" "exited on signal") OR ("nginx" "segfault at"))
| bin _time span=1h
| stats count as crashes by host _time
| sort - crashes

# NGINX starting any program other than itself (Sysmon EID 1 / EDR)

index=* earliest=-14d@d ParentImage="*/nginx" Image!="*/nginx"
| stats count values(CommandLine) as cmds min(_time) as first max(_time) as last by host Image User
| sort first

# one source sending 50 GiB or more into port 443 and receiving under a twentieth of that back

index=* earliest=-14d@d dest_port=443 bytes_in=*
| stats sum(bytes_in) as inbound sum(bytes_out) as outbound count as flows by src dest
| where inbound >= 53687091200 AND inbound > 20 * outbound
| sort - inbound

# SCTP module loaded on demand (Sysmon EID 1 / EDR)

index=* earliest=-14d@d Image="*/modprobe" (CommandLine="*sctp*" OR CommandLine="*proto-132*")
| stats count min(_time) as first max(_time) as last values(CommandLine) as cmds by host

# SCTP module initialised (kernel log)

index=* earliest=-14d@d "sctp: Hash tables configured"
| stats count min(_time) as first max(_time) as last by host



// worker crash canary: NGINX error log and kernel log, per host per hour

FROM logs-*
| WHERE @timestamp > NOW() - 14 days
| WHERE message LIKE "*worker process*exited on signal*" OR message LIKE "*nginx*segfault at*"
| EVAL bucket = DATE_TRUNC(1 hour, @timestamp)
| STATS crashes = COUNT(*) BY host.name, bucket
| SORT crashes DESC

// NGINX starting any program other than itself (endpoint process events)

FROM logs-*
| WHERE @timestamp > NOW() - 14 days AND event.category == "process"
| WHERE process.parent.name == "nginx" AND process.name != "nginx"
| STATS count = COUNT(*), cmds = VALUES(process.command_line), first = MIN(@timestamp), last = MAX(@timestamp) BY host.name, process.name, user.name
| SORT first

// one source sending 50 GiB or more into port 443 and receiving under a twentieth of that back

FROM logs-*
| WHERE @timestamp > NOW() - 14 days AND destination.port == 443 AND source.bytes IS NOT NULL
| STATS inbound = SUM(source.bytes), outbound = SUM(destination.bytes), flows = COUNT(*) BY source.ip, destination.ip
| WHERE inbound >= 53687091200 AND inbound > 20 * outbound
| SORT inbound DESC

// SCTP module loaded on demand (endpoint process events)

FROM logs-*
| WHERE @timestamp > NOW() - 14 days AND event.category == "process" AND process.name == "modprobe"
| WHERE process.command_line LIKE "*sctp*" OR process.command_line LIKE "*proto-132*"
| STATS count = COUNT(*), first = MIN(@timestamp), last = MAX(@timestamp), cmds = VALUES(process.command_line) BY host.name

// SCTP module initialised (kernel log)

FROM logs-*
| WHERE @timestamp > NOW() - 14 days AND message LIKE "*sctp: Hash tables configured*"
| STATS count = COUNT(*), first = MIN(@timestamp), last = MAX(@timestamp) BY host.name
